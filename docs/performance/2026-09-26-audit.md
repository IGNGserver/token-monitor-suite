# Repository performance audit — 2026-09-26

## Scope and method

Reviewed the current desktop package and startup imports, main-to-renderer snapshots, renderer visibility and render path, collector/watch lifecycle, limits scheduling, Hub aggregation/SSE, headless packaging, Android release settings, and the separate site. The workspace contained unrelated in-progress Android and shared-UI changes; this audit did not edit those paths. Measurements below are local Linux/Node observations, not cross-platform end-to-end claims.

## Confirmed costs and changes

| Path | Evidence | Change |
|---|---|---|
| Desktop and agent startup | `src/shared/tokscaleUpdater.js` imported `tar` at module load; extraction is used only after an explicit tokscale download. | Load `tar` inside `extractTarball()`. Version checks and normal startup no longer initialize the archive parser. |
| Main-to-renderer updates | `flushPush()` sent each coalesced snapshot to a hidden or minimized BrowserWindow. Earlier instrumentation in this path found a roughly 1.3 MB structured-clone payload; this audit confirmed the unconditional send in the current source. The single pending slot could also let a later health event replace stats in the same 200 ms window. | Keep one pending stats payload and one pending lightweight event, suppress hidden-window IPC, and replay one latest stats snapshot plus current sync health on show/restore. Collection, exports, and main-process read paths keep running. |

Seven separate Node processes per condition for the updater import; numbers are medians. The machine had a live Token Monitor installation and active tokscale scans, so import wall time is noisy and should not be read as whole-app startup time.

| Isolated updater import | Before | After |
|---|---:|---:|
| Retained JS heap after GC | 4,212,520 B | 3,580,968 B (631,552 B lower) |
| RSS delta after GC | 23,314,432 B | 21,975,040 B (1,339,392 B lower) |
| Loaded CommonJS modules | 87 | 86 |
| Wall time median | 674 ms | 494 ms (high variance; no reliable latency claim) |

The hidden-window behavior test feeds 100 separate flushed stats updates: the old delivery path would send 100 IPC snapshots; the new path sends 0 while hidden and 1 latest stats snapshot plus 1 sync-health event on reveal. A queued newer snapshot replaces the deferred one; a later health event in the same coalescing window cannot erase it. This is a deterministic delivery count, not a measured whole-app CPU or memory reduction.

## Package size and other paths

The final Linux directory package is 323,027,323 logical bytes (308.06 MiB). Its Electron executable is 221,064,440 B (210.82 MiB), the native tokscale binary 26,921,648 B (25.67 MiB), and `app.asar` 10,605,831 B (10.11 MiB). `tar` remains packaged because user-initiated updates require it, so this audit makes no package-size reduction claim. Existing locale pruning removed 49 Chromium packs. The Hub image prunes its runtime dependencies, the headless archive has a scoped manifest, and the separate site is outside the desktop file allowlist. No safe, high-impact dependency or Chromium component deletion was established.

Collector watch roots default to native events with bounded polling fallback, watch ticks reuse a full-scan anchor, and period scans are serial to avoid tripling peak I/O/CPU. Limits refresh has concurrency, deadline and retry controls. Hub stats has in-flight/cache sharing, skips broadcast work without SSE listeners, and bounds slow clients. These paths have compatibility-sensitive freshness contracts and lacked a measured regression in this audit, so they were left intact. Android release shrinking and whole-app renderer/main RSS need release-equivalent or device measurements before changing them.

## Verification and limits

- `npm run verify`: 2,228 passed, 2 skipped, 0 failed; product-scope, shared-UI, CSS, Android boundary, lint and Node tests passed.
- New tests exercise deferred/replayed stats, a queued newer snapshot, mixed stats/health coalescing, minimized windows, and lazy `tar` loading.
- A fresh Linux `--dir` build succeeded. All 275 present source/asset files checked in ASAR matched the workspace byte-for-byte. The packaged updater loaded under Electron's Node mode with `tar` absent from its module cache, and the packaged `tar` parser remained importable for explicit downloads.
- This checkout's `node_modules/.bin/electron-builder` shim could not resolve its own `./out/cli/cli`; the successful build invoked `node node_modules/electron-builder/cli.js` with the same config and `--dir` arguments. No package script or dependency was changed for this local install issue.
- The packaged app also launched under Wayland for 20 seconds with an empty inherited environment and temporary user/config directories. One short-lived `/proc/*/smaps_rollup` sample showed PSS of 86,316 KiB for main, 62,783 KiB for renderer, 81,877 KiB for GPU and 14,267 KiB for the network utility. This used `--no-sandbox`, an empty collector home, and no before-build comparison, so it only bounds this isolated startup sample; it is not normal-user memory or idle-CPU acceptance.
- The first temporary package was built while source files were changing and contained inconsistent ASAR offsets. It was discarded and rebuilt; no corrupted artifact was delivered.
- No startup-to-interactive, sustained idle CPU, before/after whole-app PSS, Android device, Windows/macOS, or real provider/Hub workload was measured. The existing installed app was observed read-only and was not restarted or used as an after-change comparison.
