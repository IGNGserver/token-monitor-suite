# Performance audit — 2026-09-19

## Scope and baseline

Audited the repository's packaging/dependency configuration, Electron main/renderer boot and data flow, shared collector/limits scheduling, Hub aggregation/SSE/static delivery, and Android/website build surfaces. Dynamic measurement focuses on reproducible Node hot paths and Linux package contents. This is not a claim that every platform or provider was profiled.

Baseline: `e558d051adbc91a5c2c88dd16df7093a3f1d72c2` (0.47.0), Node 24.18.0, Linux x64. The workspace already contained documentation edits, and additional documentation edits appeared during the audit. These were preserved. No release, deployment, dependency addition, or version bump was performed.

## Implemented improvements

| Path | Confirmed cost | Change |
|---|---|---|
| `src/shared/outboundFetch.js` | Importing the helper eagerly loaded the external undici stack even without a proxy. | Load undici only after resolving a configured proxy; keep native fetch for direct requests and retain injected fetch/dispatcher behavior. |
| `src/electron/main.js` | Native update downloader was imported at process startup, although its configuration is only called when downloading an update. | Defer `electron-updater` until that existing configuration point. Background update metadata checks retain their existing behavior. The module remains packaged. |
| `src/shared-ui/core/data.js` | Every session became a full display row before truncation; the sort comparator repeatedly parsed dates. | Sort lightweight candidates with one parsed timestamp each, then format only the requested page. Default remains 200 rows. |
| `src/shared-ui/core/format.js` | Repeated ICU formatter construction in limits, account and device/session rows. | Bound the relative formatter cache; reuse date formatters within a render turn, clearing at the microtask boundary so later renders observe timezone changes. |
| `src/shared-ui/app.js` | Hidden windows/tabs still rebuilt the entire content DOM on snapshots. | Keep current state while hidden and perform one pending render on visibility restoration. Visible interaction remains synchronous. Collection and synchronization continue. |
| `src/shared-ui/app.js` | Rates and health were fetched sequentially at boot. | Start both together, await both before connecting, retain fallback rates and authentication behavior. |
| `src/electron/renderer/` | Relative shared-UI and image paths resolved outside the actual source/asset directories. | Correct paths and test filesystem reachability, including the packaged ASAR. This was a pre-existing boot correctness issue, not a measured startup-speed improvement. |

Updated the Hub source build registry through `npm run update:hub-build` because shared runtime source changed.

## Quantitative results

Seven isolated Node processes per condition, medians. See `2026-09-19-benchmark.json` for raw summary output.

| Scenario | Before | After | Interpretation |
|---|---:|---:|---|
| Direct HTTP helper initialization | 192.97 ms | 0.414 ms | No proxy; removes eager external HTTP module initialization. |
| Retained JS heap for that helper | 5.83 MB | 0.108 MB | GC-normalized module delta, not whole-app memory. |
| RSS delta for that helper | 30.56 MB | 1.44 MB | Isolated-process observation; allocator/ICU effects mean this is not an additive desktop saving. |
| Session page: 200 visible / 20,000 total | 269.65 ms | 35.77 ms | Approximately 87% less processing time. |
| Heap delta during that session call | 16.48 MB | 8.89 MB | Before a subsequent GC; allocation-pressure indicator, not retained heap or peak RSS. |
| 1,000 relative-time fields | 46.78 ms | 2.00 ms | Same locale and timestamp inputs. |
| 1,000 reset-time fields | 133.54 ms | 3.05 ms | Reuses the formatter during a synchronous render turn. |
| Hidden updates, deterministic behavior test | 100 render calls | 0 DOM writes hidden; 1 on return | Latest snapshot retained. Not a measured idle CPU percentage. |
| Boot rates + health | Sequential | Concurrent | Critical dependency latency changes from sum to maximum; no real-network timing claim. |
| Linux unpacked logical file bytes | 322,777,584 | 322,779,624 | +2,040 bytes; no meaningful package size reduction. |
| Linux `app.asar` bytes | 10,356,092 | 10,358,132 | Same dependency set; small code increase. |

The fixture represents a large historical archive, not an assertion that every user has 20,000 sessions. Date formatting and session measurements are not combined into a claimed end-to-end speedup. The downloader's deferred load is established by source/lifecycle inspection; no total main-process startup saving is claimed.

## Audit conclusions outside the changed paths

- **Package/bundle size:** Rebuilt the current revision rather than comparing against stale `dist/` artifacts. Existing configuration already excludes Hub-only dependencies, maps and documentation, and removed 49 unused Chromium locale packs during the build. The unpacked application remains approximately 307.82 MiB. Chromium and the native tokscale binary dominate the lower bound. Discord's REST dependency is actually imported by its RPC client; removing it would break the dependency closure. No safe, substantial additional deletion was established. No compressed installer size improvement is claimed.
- **Headless and Docker:** Existing scripts already scope headless dependencies and prune Hub-only installation contents. Electron is a development dependency for the source install and excluded by the headless production install. Replacing the runtime/framework solely to cut size is outside this measured optimization.
- **Collector/background work:** Current code already has native watch support with polling fallback, root reuse, self-generated event filtering, serial scans, period deltas and a separate WSL anchor. Preserve these correctness-sensitive behaviors. No change to detection cadence, provider polling, sync/upload intervals or data retention was made without a measured regression.
- **Limits lifecycle:** Existing lanes, concurrency bounds, deadlines and retry scheduling provide controls for background work. No sustained provider workload was run; resource-leak absence is not proven by inspection.
- **Hub CPU/network:** `getStats` already shares an in-flight computation and caches results; broadcasts serialize one payload for all SSE listeners and skip work when there are no listeners. Backpressure is bounded. Existing tests cover minimal ingest responses and slow SSE clients. Static delivery streams files with caching headers; compression/revalidation may be useful for a WAN deployment, but no network bottleneck was measured here, so no speculative server cache was added.
- **Renderer memory/IPC:** Hidden DOM work is reduced, but incoming IPC snapshots are still delivered and retained. Suppressing main-to-renderer delivery would need a tested restore/replay contract. No claim is made that large snapshot duplication or all renderer memory costs have been eliminated.
- **Android:** Release configuration currently disables minification. R8/resource shrinking is a potential package-size follow-up, requiring a signed/release-equivalent build and runtime checks for reflection/serialization, Room, Hilt and networking. It was not enabled blindly; Android build/device performance was not measured in this audit. Lifecycle-aware UI collection is already present.
- **Marketing site:** Separate static surface with about 916 KiB of assets; it is outside the desktop package allowlist. No evidence that it contributes to desktop size or resident CPU.

## Verification and remaining limits

- Baseline `npm run verify`: 2,167 passed, 5 skipped, 0 failed.
- Final `npm run verify`: 2,172 passed, 5 skipped, 1 failed. Product-scope, shared-UI, CSS and lint guards passed. The sole failure is `configuration reference sends provider accounts to the Hub` in `tests/docs/readmeConsistency.test.js`: the independently edited `docs/configuration.md` no longer contains the exact expected phrase `does not discover local developer-tool accounts`. This audit did not modify that document or loosen its test. The full working tree is therefore **not entirely green**.
- New behavior tests cover hidden/latest-state rendering, concurrent boot/failure fallback, supported locales, off-page session formatting, direct HTTP lazy loading and desktop asset paths.
- Additional differential check: 30 mixed-date, invalid-date, tie, filtering and pagination scenarios produced byte-identical JSON for old/new session rows.
- Linux directory packaging passed. Using Electron in Node mode, the packaged collector/helper and runtime packages (`chokidar`, `dotenv`, `semver`, `tar`, `undici`, `electron-updater`, Discord RPC and `koffi`) loaded; shared UI and asset targets existed inside ASAR.
- A controlled graphical Electron boot was attempted with temporary settings and a fixture bridge. The headless environment could not establish a usable graphical/EGL session; a second GPU-disabled attempt also produced no usable app measurement. These attempts are **not** evidence of UI acceptance. No product GPU/sandbox flags were changed.
- Real renderer/main-process RSS, startup-to-interactive, long-running idle CPU, physical GPU behavior, authenticated Hub/provider E2E, Windows/macOS builds and Android acceptance remain **NOT PROVEN / NOT RUN**. The successful package load check does not substitute for these.
